# Контрольная работа №3 🐝

## 🦄 Как сдавать работу

1. Выполните задания в **отдельном репозитории** (рекомендуется: один репозиторий на одну контрольную работу).
2. Загрузите исходный код в репозиторий (`commit` + `push`).
3. В **СДО** прикрепите ответ в виде **ссылки на репозиторий с решением**.

> **Рекомендации к оформлению репозитория:**
>
> - Проект должен **запускаться** и быть готов к проверке (например: `main.py`/`app.py`, `models.py`, `database.py` и др. — по необходимости).
> - Добавьте зависимости: `requirements.txt` или `pyproject.toml`.
> - В `README.md` кратко опишите:
>   - как установить зависимости и запустить приложение (`uvicorn ... --reload`);
>   - как тестировать ключевые эндпоинты (можно командами `curl`).
> - Если используются переменные окружения (например, `MODE`, `DOCS_USER`, `DOCS_PASSWORD` и т.п.) — добавьте файл **`.env.example`** и **не публикуйте реальные секреты**. Файл `.env` должен быть в `.gitignore`.

## 🌟 Задание 6.2

Расширьте приложение **FastAPI**, реализовав **безопасную аутентификацию** с использованием хеширования паролей и защиты от тайминг-атак. Вам потребуется переиспользовать код из предыдущего задания, следуя принципу **Don't Repeat Yourself (DRY)**.

**1. Создание моделей данных**

- Опишите Pydantic‑модель **UserBase** с полями:
    - `username:` строка, обязательное поле

- Опишите Pydantic‑модель **User**, которая наследуется от **UserBase**, с полями:
    - `username:` строка, обязательное поле (будет отнаследовано)
    - `password:` строка, обязательное поле

- Опишите Pydantic‑модель **UserInDB**, которая наследуется от **UserBase**, с полями:
    - `username:` строка, обязательное поле (будет отнаследовано)
    - `hashed_password:` строка, обязательное поле

> **Примечание:** в модели для хранения в базе (`UserInDB`) не должно быть поля с открытым паролем — только его хеш.

**2. Настройка PassLib**

Инициализируйте `CryptContext` с алгоритмом `Bcrypt` для генерации и проверки хешей паролей.

**3. Зависимость аутентификации**

Реализуйте функцию `auth_user`, которая:
- Извлекает `username` и `password` из заголовка `Authorization` через `HTTPBasicCredentials`.
- Находит пользователя в in‑memory базе (словарь/массив `fake_users_db`).
- Проверяет корректность пароля с помощью метода `verify` из вашего `CryptContext`.
- Для сравнения логин‑строк используйте `secrets.compare_digest()`.
- При успехе возвращает объект юзера. В случае неудачи выбрасывает `HTTPException` со статусом `401` и заголовком `WWW-Authenticate: Basic`.

**4. Реализация маршрутов `/register` и `/login`**

Добавьте POST‑эндпоинт `/register`, который:

- Принимает тело запроса в формате JSON, соответствующее модели **User**.
- Генерирует хеш пароля с помощью `CryptContext`.
- Создаёт объект по модели **UserInDB** и сохраняет его в in‑memory базе `fake_users_db`.
- При успешной регистрации возвращает сообщение об успешном добавлении пользователя

Добавьте GET‑эндпоинт `/login`, который принимает автоматически подставленный через `Depends` результат работы `auth_user` и возвращает JSON с приветствием:

- При успешной аутентификации: статус **200** и тело ответа вида:

```json
{ "message": "Welcome, <username>!" }
```

                  
- При ошибке: статус **401** и заголовок `WWW-Authenticate: Basic`.

**5. Тестирование через `curl`**

```bash
# Регистрация
curl -X POST -H "Content-Type: application/json" -d '{"username":"user1","password":"correctpass"}' http://localhost:8000/register

# Успешный логин
curl -u user1:correctpass http://localhost:8000/login

# Неверный пароль
curl -u user1:wrongpass http://localhost:8000/login
```
                  
**6. Обработка ошибок (опционально)**

- Если в заголовках отсутствуют `username` или `password`, FastAPI автоматически вернёт 401.
- Для кастомных сценариев используйте `HTTPException` с добавлением `headers={"WWW-Authenticate": "Basic"}`.

**3. Отключение документации в PROD-режиме**  
В режиме `PROD`:

- Полностью скройте эндпоинты `/docs`, `/openapi.json`, `/redoc`.

- Используйте условные проверки режима при инициализации приложения.

- Убедитесь, что в PROD-режиме схема OpenAPI не генерируется или недоступна.

**5. Тестирование**

DEV-режим:

```bash
curl -u valid_user:valid_password http://localhost:8000/docs
```

PROD-режим:

```bash

```

- **Маршрут:** `POST /login`
- **Логика:**
    - Если пользователя нет в БД, верните **404 Not Found** с сообщением `{"detail": "User not found"}`.
    - Если пользователь есть, сравните хэш принятого пароля с сохранённым хэшем. При поиске в БД для сравнения `username` используйте **модуль** `secrets`, чтобы избежать тайм-атак.
    - При успешной проверке верните JWT-токен (`access_token`) с полезной нагрузкой `{"sub": username}`.
    - Если пароль неверен, верните **401 Unauthorized** с сообщением `{"detail": "Authorization failed"}`.

**3. Внедрите Rate Limiter (ограничение количества запросов)**

- Установите ограничения:
    - **/register:** 1 запрос в минуту (защита от спама).
    - **/login:** 5 запросов в минуту (ограничение попыток ввода пароля).

- При превышении лимита возвращайте **429 Too Many Requests** с сообщением `
{"detail": "Too many requests"}`, если будете самостоятельно реализовывать такую логику (при использовании библиотек уже встроена логика ответа с этим статус кодом).

### Требования к реализации

- Используйте `passlib` для хэширования паролей (рекомендуется алгоритм `bcrypt`).
- Для сравнения username применяйте `secrets.compare_digest()`.
- Для `rate-limiting `можете использовать библиотеку `slowapi` или `fastapi-limiter`.
- Храните пользователей в памяти (например, в словаре или списке) с хэшами паролей.

    - Закрывает соединение
    - Возвращает `{"message": "User registered successfully!"}`

5. Протестируйте API с помощью команды:

```bash
curl -X 'POST' 'http://127.0.0.1:8000/register' \
-H 'Content-Type: application/json' \
-d '{"username": "test_user", "password": "12345"}'
```
               
**Требования к коду:**

- Используйте синтаксис из лекции (без SQLAlchemy)
- Названия таблицы и полей должны точно совпадать с условием (`users`, `username`, `password`)
- Не забудьте про `IF NOT EXISTS` при создании таблицы
- Пароль пока можно хранить в открытом виде (без шифрования)

**Проверьте, что:**

- Таблица создается без ошибок
- Эндпоинт возвращает успешный ответ
- Данные появляются в базе (можно проверить через DB Browser for SQLite)
